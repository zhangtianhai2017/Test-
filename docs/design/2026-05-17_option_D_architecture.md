## 一句话定义

**D 方案 = 生成器是一个 PyTorch 神经网络;能用梯度更新的地方用梯度,过不去渲染那一段用强化学习兜底,管线其它部分保持现状。**

## 2. 信号流(梯度 vs 奖励)

| 信号来源 | 走哪条路 | 更新生成器的方式 |
|---|---|---|
| **符号 fitness**(隐私覆盖、比例、颜色调和等不需要看图的) | 直接计算 → 数值损失 → autograd 反传到生成器 | **真梯度** |
| **J 视觉判官**(需要看渲染图才能判断的:整体美感、bug、风格) | reward 标量 → REINFORCE / PPO 估计梯度 | **策略梯度**(不是真梯度,是 reward 加权的策略梯度估计) |

**两套信号**线性加权 → 生成器**同时学**"我配置参数合不合理"和"渲染出来好不好看"。

## 3. 要建的具体组件(deliverables)

### 组件 1:**生成器 NN**
- 输入:文本 brief(CLIP 编码,768 维)
- 网络:文本编码器(冻结)+ 3 层 MLP(可训)+ 多头输出
- 输出:
  - 连续参数(HSL、对称、几何 ratio 等):**直接输出实数**
  - 离散参数(cup_id、fabric_id、pattern 等):**输出 softmax 分布,采样得离散值**
- 框架:PyTorch
- 规模:很小(几 MB),训练几分钟就能迭代一次

### 组件 2:**符号 fitness 模块**
- 输入:outfit config(不渲染)
- 输出:多项标量分(每项 0-1)
- 计算项:
  - 隐私种子覆盖是否够
  - 几何比例是否在审美区间
  - 颜色 H/S/L 是否调和(色相对比、明度对比)
  - 库条目兼容性(seam ↔ fabric ↔ cup)
  - 对称度是否在二值区间(不是含糊的中间状态)
- 实现:纯 PyTorch 函数,可 autograd
- 速度:每件 ~1 ms

### 组件 3:**J 视觉判官**
- 已选定:**Qwen2.5-VL-7B 本地部署**
- prompt 已设计好(区分结构 bug vs 风格非常规)
- 输出:pass/fail(布尔)+ 1-10 评分 + 缺陷列表
- 速度:每件 ~1-2 秒

### 组件 4:**训练循环**
- 一次迭代:
  1. 从生成器采 N 个 config(N=32)
  2. 算 N 个符号 fitness → 损失 1
  3. 渲染 N 个 → J 评分 → 损失 2(REINFORCE)
  4. 加权合并损失 → backprop → 更新生成器
- 框架:PyTorch + 我们的渲染管线 + 本地 vLLM 调 J
- 数据日志:每迭代记 (text, config, render, J_verdict, sym_score)

### 组件 5:**数据回路**
- 每次训练日志落盘
- 累积成"语料库",将来:
  - 训 reward 模型替代部分 J 调用(降本)
  - 训生成器 V2(VAE / Diffusion,M2 阶段)

## 4. 训练过程(具体怎么跑)

### 阶段 1:**预训练(数据收集 + bootstrap)**
- 用现有 `random_outfit + diverse_batch` 生成 ~500 件
- 每件用符号 fitness + J 评一遍
- 得到 (text, config, score) 数据集
- 用这些数据**监督预训练**生成器(让它先模仿"高分配置")

### 阶段 2:**在线学习(主循环)**
- 每次 32 件:
  - 生成器采样 → 评估 → 损失 → 更新
- 几百次迭代后,生成器学会:
  - 高符号 fitness(直接梯度督促)
  - 高 J 通过率(REINFORCE 督促)
- **完全自动化**,不需要人介入

### 阶段 3:**人在回路(可选,产品化)**
- 用户从 J pass 的输出里挑喜欢的
- 这些"被挑中"的配置作为额外 positive signal
- 喂回训练,生成器进一步贴近用户口味

## 6. 这个方案**不做**什么(避免误会)

- ❌ **不**改渲染管线(继续用 Open3D)
- ❌ **不**把几何 / shell / polish 改写成 torch.Tensor
- ❌ **不**做可微渲染(NVDiffRast 那类)
- ❌ **不**做新拓扑生成(M3+ 的事)
- ❌ **不**追求"完全端到端 backprop"(那是方案 A,需要 1-3 个月)

---

## 7. 方案 D 的本质

**用"分而治之"绕开渲染不可微**:
- 简单的、不依赖图像的判断(覆盖、比例、颜色调和)用**真梯度**学
- 复杂的、需要看渲染图的判断(美感、bug)用**RL 奖励信号**学
- 两套信号同时驱动生成器,工程量 = 一个 NN + 一个符号评分函数 + 一个本地 LLM 推理

**4 周内拿到一个真的会自己学习的泳衣设计生成器**。
