# 给 3090 那边 AI 的部署指导:vLLM + Qwen2.5-VL-7B + 隧道

> 这份文档是 Python 端 Claude 写给负责管你 3090 那台机器的 AI 的。
> 任务很具体:**在 3090 上跑 Qwen2.5-VL-7B 视觉模型,通过隧道暴露成
> OpenAI 兼容 API,把 URL 告诉我们,我们这边的 RL 训练就能开始用它当
> "视觉判官"了。**

---

## 背景(2 行)

我们这边在做泳装自动设计生成器,生成器是个 PyTorch NN,渲染后需要一个
视觉模型判断"这是不是一件结构上合理的泳装"(不评审美,只看 bug)。
模型选了 **Qwen2.5-VL-7B-Instruct**,理由:中文友好、本地能跑、视觉能力够。

## 你要做的事

1. 装 vLLM
2. 启动 vLLM serve 加载 Qwen2.5-VL-7B
3. 起一个隧道(推荐 Cloudflare Quick Tunnel,免账号)
4. 把隧道 URL 报回来
5. 保持服务运行(后台 / tmux)

---

## Step 1:环境前置检查

```bash
# 验证 GPU
nvidia-smi
# 应看到一张 RTX 3090,显存 24576 MiB

# 验证 CUDA
nvcc --version    # 期望 CUDA 12.x
# 或
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

# Python 版本(vLLM 需要 3.10+)
python --version
```

如果 CUDA 没装好,**先停下来**告诉用户;不要试图自己装 NVIDIA 驱动。

## Step 2:装 vLLM

```bash
# 用独立 venv,不要污染系统 Python
python -m venv ~/venvs/vllm
source ~/venvs/vllm/bin/activate

pip install --upgrade pip
pip install vllm
```

**装完后验证**:
```bash
python -c "import vllm; print(vllm.__version__)"
```

注意:**Qwen2.5-VL** 系列要求 vllm >= 0.6.6(2024 末新加的支持)。如果版本太旧,`pip install -U vllm`。

## Step 3:启动 vLLM 服务

第一次运行会从 HuggingFace 拉模型(约 15 GB),需要几分钟。建议放后台跑并把日志重定向:

```bash
# 拉模型并启动(后台 + 日志)
nohup vllm serve Qwen/Qwen2.5-VL-7B-Instruct \
    --port 8000 \
    --host 0.0.0.0 \
    --gpu-memory-utilization 0.85 \
    --max-model-len 8192 \
    --max-num-batched-tokens 4096 \
    --trust-remote-code \
    > ~/vllm.log 2>&1 &

# 跟踪日志,等到看见 "Application startup complete" 或 "Uvicorn running"
tail -f ~/vllm.log
```

启动需要约 1-2 分钟(加载权重)。

**关键参数解释**:
- `--gpu-memory-utilization 0.85`:留 ~3.6 GB 显存余量,避免被其他进程挤崩
- `--max-model-len 8192`:够用,不要太大省显存
- `--host 0.0.0.0`:必须,否则隧道连不上
- `--trust-remote-code`:Qwen 系列要求

**显存预期**:Qwen2.5-VL-7B fp16 + KV cache ≈ **18-20 GB**,3090 24GB 完全够。

## Step 5:起 Cloudflare 隧道(免账号)

Cloudflared 的"快速隧道"无需注册账号,直接给一个临时 URL:

```bash
# Linux 安装
curl -L --output cloudflared.deb \
    https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb

# 启动快速隧道(也放后台)
nohup cloudflared tunnel --url http://localhost:8000 > ~/tunnel.log 2>&1 &

# 等 10-30 秒,看日志找 URL
sleep 15 && cat ~/tunnel.log | grep "trycloudflare.com"
```

应该能看见类似:
```
https://something-words-here.trycloudflare.com
```

**这个 URL 就是要发回来的东西**。

```

# ... 重新 nohup 启动 ...
```

## 常见问题

| 症状 | 处理 |
|---|---|
| 拉模型卡住 | 网络问题;`export HF_ENDPOINT=https://hf-mirror.com` 用国内镜像 |
| OOM 启动失败 | 降 `--gpu-memory-utilization 0.75`,或确认显存没被别的进程占 |
| `KeyError: Qwen2_5_VLForConditionalGeneration` | vllm 版本太旧,`pip install -U vllm` |
| 隧道 502 | vLLM 还没启完,等 30 秒;或本地 curl 验证一下端口 |
| 推理乱码 | 升级 vllm + tokenizer:`pip install -U vllm transformers` |

## 不要做的事

- 不要装 NVIDIA 驱动(由用户决定)
- 不要 reboot 系统
- 不要装 Docker(没必要)
- 隧道不要用 ngrok 付费功能(免费够用)
- 不要把 vLLM 暴露在 8000 端口的公网(只走隧道)
