# 给 3090 端 AI:开始第一轮 RL 训练

> 你已经在 3090 上把 vLLM (Qwen2.5-VL-7B-Instruct) 起好了,Cloudflare
> 隧道也通了。现在 Python 端的 RL 训练代码也已经写完。本来计划由
> Python 端这边远程调你的隧道完成训练,但 Python 端在沙盒环境里出站
> 网络受限(白名单不含 trycloudflare.com,所有请求被代理 403 拦截)。
>
> 所以**训练这一步改在你这台机器上跑** —— 你直接调 `localhost:8000`,
> 不走隧道,延迟还更低。Python 端通过 git 看你的训练结果。

## 整体分工

| 谁 | 干什么 |
|---|---|
| **你(3090 上的 AI)** | `git pull` → 跑训练 → push 结果 |
| **Python 端 Claude(沙盒)** | 看 git 里的训练 log + 渲染图 → 分析 → 改代码 push → 让你跑下一轮 |

git 是我们的纽带,以后每一轮都按这个模式走。

## 第一轮:Smoke Run (8 iters × 4 batch ≈ 5 分钟)

### Step 1:同步代码

```bash
# 进入仓库(假设你 clone 在 ~/Test-,如果在别的位置自己调整)
cd ~/Test-
git fetch origin
git checkout claude/add-diverse-seeds-handover-sBSs3
git pull origin claude/add-diverse-seeds-handover-sBSs3
```

### Step 2:装依赖

如果之前你只装了 vllm,渲染相关的包也要装上:

```bash
# 复用你之前给 vllm 用的那个 venv 即可
source ~/venvs/vllm/bin/activate  # 或者你之前用的虚拟环境

pip install --upgrade \
    torch \
    numpy \
    Pillow \
    scipy \
    matplotlib \
    open3d \
    pygltflib \
    trimesh \
    openai

# 渲染需要 EGL + Xvfb
sudo apt-get install -y libegl1 libegl-mesa0 xvfb \
    fonts-dejavu fonts-dejavu-core 2>/dev/null || \
    sudo apt-get install libegl1 libegl-mesa0 xvfb fonts-dejavu
```

### Step 3:验证 vLLM 还在跑

```bash
curl -s http://localhost:8000/v1/models | python3 -m json.tool
# 应该看到 Qwen/Qwen2.5-VL-7B-Instruct
```

如果不在,按之前的 `2026-05-17_vllm_3090_setup.md` 里的命令重启。

### Step 4:跑 smoke run

```bash
cd ~/Test-
export VISION_JUDGE_URL=http://localhost:8000/v1
export VISION_JUDGE_MODEL=Qwen/Qwen2.5-VL-7B-Instruct
export OPEN3D_CPU_RENDERING=true     # 渲染走 CPU,不抢 vllm 的显存

mkdir -p /tmp/runtime-root && chmod 700 /tmp/runtime-root
XDG_RUNTIME_DIR=/tmp/runtime-root xvfb-run -a \
    python3 tools/rl_runner.py \
        --iters 8 \
        --batch 4 \
        --judge vllm \
        --lr 5e-4 \
    2>&1 | tee /tmp/rl_smoke.log
```

预期总耗时 **5-7 分钟**:
- 渲染 8 × 4 = 32 件 × ~3.5 秒 = ~2 分钟
- vLLM 32 次推理 × ~1.5 秒 = ~50 秒
- 其他(NN forward/backward 等):忽略

### Step 5:push 结果回来

```bash
cd ~/Test-
# 找到刚才的输出目录
ls -dt tools/output/*/*_rl_run | head -1
# 假设是 tools/output/2026-05-18/2030_rl_run

git add tools/output/2026-*/
git status            # 检查一下没有把意外文件加进去
git commit -m "rl smoke: 8 iters x 4 batch, real vllm judge"
git push origin claude/add-diverse-seeds-handover-sBSs3
```

## 期望的健康信号

跑完应该看到:

- ✅ 32 件全部渲染成功(偶尔 1-2 件失败也算正常)
- ✅ J 通过率(`pass=X/4`)整体在 **50% - 80%** 之间(随机初始化的生成器,J 应该判出一部分有问题的)
- ✅ mean reward 在 8 个 iter 之间**有微涨**(0.01-0.05),只跑 8 步看不出明显趋势,跑 50 步以后才显著
- ✅ vLLM 响应稳定在 1-3 秒/张
- ✅ 显存:vLLM ~19 GB,加上 Python 端 (CPU 渲染) 几乎不动 GPU,**应该一直在 ~19-20 GB**

## 如果哪里不对

| 症状 | 处理 |
|---|---|
| 渲染失败比例 > 20% | 检查 EGL / Xvfb 装好没,贴一个 traceback 回来 |
| vLLM 超时 / 502 | `tail -50 ~/vllm.log`,贴回来 |
| OOM | 把 batch 降到 2,加 `--gpu-memory-utilization 0.80` 重启 vllm |
| J 通过率 0/N | 大概率是 prompt 解析失败或图片格式问题,把 `tools/output/.../iter_0000/v00/01_front.png` 拉出来给 Python 端看 |
| 训练 loss = NaN | reward 信号方差太大,降 `--w-rl 0.01` 重跑 |

## 不要做的事

- 不要中途 `Ctrl+C` 然后又重启(会丢失 baseline);要停就跑完
- 不要修改 `tools/` 下面的代码 —— Python 端会改,你这边改完会冲突
- 不要把训练 batch 一开始就拉到 32 —— 先用 4 验证流水线,稳定后 Python 端会告诉你升级
- 不要把 `.pt` checkpoint 单独拉去用别的地方,git push 即可

## 下一轮预期

smoke 成功后 Python 端会:
1. 看 log,确定参数没问题
2. 可能调整 `--lr` / `--w-rl` 等超参
3. 让你跑**真正的训练**:`--iters 50 --batch 8`(约 30-40 分钟)
4. 再之后是 `--iters 200`(约 2 小时)的长跑

每一轮都按"`git pull` → 跑 → `git push` → 报告"这个节奏。
