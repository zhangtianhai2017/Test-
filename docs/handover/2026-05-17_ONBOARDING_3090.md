# 给 3090 端 Claude 的接手指令

> 把这个文件的 URL 发给 3090 上的 Claude session,告诉它"读这个,然后开始执行"。其他不用说。

---

## 你是谁,要做什么

你是接手这个项目 GPU 端工作的 Claude session,**在用户的 3090 机器本地运行**。

另一个 Claude session 在受限沙盒里负责代码工程,通过 git 和你协作。这个分工是因为沙盒那边出站网络受限,**只有你能调本地 vLLM**。

任务:**跑一轮 RL 训练 smoke run,把结果 push 回仓库 + 报告给用户**。

---

## 立即执行(按顺序)

### 1. 读项目永久记忆和当前架构

```
读以下文件,理解项目状态:
  - CLAUDE.md                                        ← 项目永久记忆,必读
  - docs/design/2026-05-17_option_D_architecture.md  ← 当前架构(option D)
  - docs/handover/2026-05-17_rl_training_on_3090.md  ← 你这一轮要执行的步骤
```

### 2. 按 `docs/handover/2026-05-17_rl_training_on_3090.md` 一步步做

那份文档已经把每一步都写好了:
- Step 1:同步代码 (`git pull`)
- Step 2:装依赖 (torch / open3d / Pillow / openai 等)
- Step 3:确认 vLLM 服务还在(localhost:8000)
- Step 4:跑 smoke run(`tools/rl_runner.py --iters 8 --batch 4 --judge vllm`)
- Step 5:git commit + push 结果
- Step 6:按指定格式报告

**不需要等用户授权每一步** —— 用户已经把这份指令书面授权给你了,按文档走就行。遇到 sudo / 装包之类 Claude Code 会自动提示用户确认,正常等几秒。

### 3. 跑完之后

把 `docs/handover/2026-05-17_rl_training_on_3090.md` Step 6 那个"报告模板"填好,**贴回给用户**(用户会转发给 Python 端的 Claude)。

---

## 出错怎么办

- 先查文档 Step 6 后面的"如果哪里不对"小节
- 真不知道的,把完整错误信息 + 你在哪一步、跑的什么命令,贴回给用户

**不要自己改 `tools/` 下面的代码** —— Python 端会改,你改了 git pull 会冲突。

---

## 工作节奏

这一轮 smoke 跑完之后,Python 端会:
1. 看你 push 上来的 log + 渲染图
2. 决定下一轮参数(可能调 lr / batch / w_rl)
3. 让你跑 `--iters 50 --batch 8`(约半小时)
4. 再之后是更长的训练

每一轮你的工作模式都是固定的:
**`git pull` → 跑命令 → `git push` → 报告**。
